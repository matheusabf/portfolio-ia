Concluído Projeto interno

Gestão do Jira: triagem automática, SLA e relatório diário

Grupo Multilaser · Líder de Suporte

01 Triagem automática

02 Relatório diário

Duas automações independentes sobre a mesma fila: uma garante que todo chamado tenha dono, a outra que nenhum fique esquecido.

Tecnologias

  • Jira REST API
  • Google Apps Script
  • Google Chat Webhook

O desafio

Na fila do suporte, dois problemas se somavam. Chamados chegavam sem responsável ou sem contato definido e ficavam parados até alguém notar, estourando o SLA de triagem. E os chamados aguardando retorno ou sem movimentação há dias simplesmente sumiam da vista do time.

A minha abordagem técnica

Resolvi com duas automações independentes em Google Apps Script, ambas integradas à REST API do Jira e avisando o time por webhook no Google Chat. A primeira varre o Jira periodicamente, encontra chamados sem responsável ou contato e faz a triagem com o usuário; com a triagem concluída, registra o SLA de triagem como cumprido, encaminha o chamado para a fila de análise e notifica o time. A segunda roda todo dia às 8h, levanta os chamados aguardando retorno ou parados há mais de 3 dias e envia um relatório ao Chat, com link direto para cada um.

O resultado

Os chamados sem dono deixaram de existir, o SLA de triagem passou a ser cumprido de forma consistente e o time começa o dia sabendo exatamente o que está parado.

Entregue Projeto interno

Módulo de envio e acompanhamento de assinatura digital

MultidadosTI · Desenvolvedor Júnior

01 Fluxo do envio

02 Telas de gestão

Do status do chamado à assinatura: o envio dispara sozinho e o andamento fica sempre atualizado.

Tecnologias

  • PHP
  • SQL
  • REST API
  • Cronjobs

O desafio

Os contratos enviados para assinatura digital eram acompanhados à mão: alguém conferia se cada documento tinha sido entregue, lido e assinado. Quando algo falhava no caminho, ninguém ficava sabendo.

A minha abordagem técnica

Desenvolvi o módulo de ponta a ponta em PHP. O envio é disparado por regras: cada uma define um status de ativação e, quando o chamado entra nele, a integração envia o contrato ao provedor via REST API. A partir daí, um cronjob lê o provedor e atualiza o status de cada envio conforme o usuário recebe, lê ou assina. Para o time, criei telas para configurar os status de ativação, cadastrar campos adicionais e acompanhar os envios — com a opção de reprocessar o que falhou.

O resultado

Rastreabilidade de cada contrato, do envio à assinatura, sem ninguém conferir nada à mão. Quando algo falha, o time vê no painel e reprocessa em um clique.

Em produção Projeto interno

Alertas em tempo real para pedidos com SLA estourado

Grupo Multilaser · Analista → Líder de Suporte

01 Fluxo do alerta

02 O que chega no alerta

O time recebe o problema já diagnosticado: qual pedido, qual erro e há quanto tempo.

Tecnologias

  • Python
  • SQL
  • Google Chat Webhook

O desafio

Pedidos com falha de integração estouravam o SLA sem ninguém perceber. Quando alguém notava, ainda precisava caçar o erro no log, um pedido por vez — e nos fechamentos, quando cada hora conta, isso pesava ainda mais.

A minha abordagem técnica

Montei uma automação que consulta as listagens dos sistemas internos e separa os pedidos com SLA estourado. Para cada um, ela busca no banco do sistema interno o log de erro correspondente e envia um alerta via webhook para um espaço no Google Chat, com o link do pedido, as informações pertinentes, o erro registrado, o tempo decorrido e o SLA.

O resultado

O time passou a receber o problema já diagnosticado, em vez de garimpar log por log. As falhas começaram a ser resolvidas dentro das janelas críticas, não depois delas.
